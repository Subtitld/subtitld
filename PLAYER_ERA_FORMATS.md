# Player-era formats: grammars for the undocumented ones

`src/subtitld/modules/legacy.py` implements eleven of these already. This
file holds the grammars recovered for the formats that have **no published
specification**, so the next batch can be written without repeating the
research. Each one was taken from a working implementation, which for these
formats is the only specification that exists.

Confidence: **solid** = working source code or a file from the originating
application. **medium** = a sample generated by Subtitle Workshop, so real
bytes but SW's idea of the format.

The richest source is URUSoft's **SubtitleAPI**, the Pascal library behind
Subtitle Workshop, GPLv3 at `github.com/DSRCorporation/subtitle-workshop`:
one read unit and one write unit per format under
`SubtitleAPI/Source/ReadFormats/` and `SaveFormats/`, with detection in
`UCheckFormat.pas`. Write our own readers from the grammar below — do not
translate its code, which is GPL.

## SubSonic (.sub) — solid

Two lines a cue, the second carrying the end time:

```
1 55.00 \ ~:\O PADRINHO II
1 62.60
```

- Separator is literally `` \ ~:\``; the text begins straight after it.
- The leading `1 ` is a constant.
- **Seconds with two decimals, wrapping every 256 s.** A reader keeps a wrap
  count, raises it whenever the value fails to increase, and the time is
  `(value + 256 * wraps)`. SW's author reverse-engineered this with a
  calculator and says so in a comment — treat it as provisional.
- One line of text only. End falls back to start + 2 s.

## Sasami2k (.s2k) — solid for parsing, undocumented semantics

A command script, not a cue list. Lines beginning `;` are directives,
everything else is subtitle text.

```
;Env.Movie.Width=320
;Set.Font.Face=Tahoma
;Buffer.Push=1
;Buffer.Pop=1
;Set.Time.Start=55000
;Set.Start.Position.x=160
;Set.Start.Position.y=203
O PADRINHO II
```

- **Integer milliseconds** in `;Set.Time.Start=`.
- **No end times**: a cue ends at the next `;Set.Time.Start=`, which SW
  writes with a single space as its text to clear the screen. Fallback is
  start + 2 s.
- Line breaks are positional: each line of text is its own file line,
  preceded by its own position block.
- To parse: drop every `;` line whose first 16 characters are not
  `;set.time.start=`, drop `//` lines, and what remains alternates time
  markers and text.
- Magic: `;Env.Movie.Width=` at offset 0.
- What `Buffer.Push/Pop`, `Set.Slot`, `Set.Time.Delay` and `Set.Alpha.*`
  mean is inferred, not documented.

## Captions 32 (.txt) — solid

Fixed columns, one line a cue, 95 characters:

| columns | content |
|---|---|
| 1–11 | start `hh:mm:ss:zz` |
| 13 | `,` |
| 15–25 | end `hh:mm:ss:zz` |
| 27 | `,` |
| 29–61 | first line of text, padded to 33 |
| 62 | `\|` |
| 63–95 | second line, padded |

`zz` is hundredths. Two lines at most; longer ones are cut at 33 characters.
The originating application was never identified.

## SBT (.sbt) — solid

```
00:01:26
00:01:29
O padrinho nasceu com o nome
de Vito Andolini,
```

Times on their own lines, written to the whole second. **Always two lines of
text**: a one-line cue carries a leading empty line. End falls back to
start + 2 s.

Do not copy SW's reader literally — it fails to skip the lines it consumed
and so starts a spurious second cue at every end timestamp. Iterate with a
cursor.

## Stream SubText (.sst player, .ssts script) — solid, with real app files

`.sst` is the player export: an `SST 2.0.x` line, a comment block,
`[PROPERTIES]` keys, then `[SCRIPT]` with **tab-separated integer
milliseconds** and a whole RTF document per cue flattened onto one line,
`~` standing in for its newlines.

`.ssts` is the project's titles file: `SST 2.0.x`, `[TITLES]`, `fps=`, then
six tab-separated fields with `hh:mm:ss.zz` times and `~` as the line break.
The real application ships a header row naming them:

```
LINE	CHAPTER	TIME-IN	TIME-OUT	TEXT	STYLE
```

**SW writes those fields in the wrong order** — it puts `Default` in CHAPTER
and `SubRip` in STYLE, while the companion `.sstt` defines a style actually
named `Default`. Follow the header, not SW.

## ViPlay (.vsf) — solid, two independent implementations

```
{* VIPLAY SUBTITLE FILE *}
00:00:55,000-00:01:02,600=O PADRINHO II
00:01:26,600-00:01:29,000=<u><b><i>first line|second line
```

Magic is the first line exactly. Times are `hh:mm:ss,zzz`, **milliseconds**,
at fixed columns: start 1–12, `-` at 13, end 14–25, `=` at 26, text from 27.
`|` breaks a line, and `<u> <b> <i>` are allowed — ViPlay is by the same
author as Subtitle Workshop and takes its tags.

## Oresme (.txt) — solid, one implementation

```
10:00:19:06{Bottom}{Open Caption}{Center}{White}{Font Arial GVP Bold}We view
```

- **`hh:mm:ss:ff`, frames**, not milliseconds; broadcast-style 10:00:00:00
  starts are normal.
- Everything in braces is a tag and is dropped; `{N}` is the line break.
- **No end times**: a cue ends just before the next one begins; an empty row
  is a clear-screen marker.
- Detection: a timecode immediately followed by `{`.

There is also an Oresme `.docx` variant, which is WordprocessingML with one
table row a cue: cell one a `TimeCode`-styled `hh:mm:ss:ff`, cell two a
`PopOn`-styled paragraph, `<w:br/>` between lines.

## Xombie (.xss) — solid; it really is an ASS dialect

Parsed only by `OpenXombieSub()` in MPC-HC's `src/Subtitles/STS.cpp`.
`Key=comma,separated,values`, `;` comments.

```
ScreenHorizontal=1280
Style=<name1>,<name2>,<font>,<size>,<col1..4>,<alpha1..4>,<bold>,<italic>,…
Line=D,<id>,<layer>,<h:mm:ss.mmm>,<h:mm:ss.mmm>,<style1>,<style2>,<actor>,<mL>,<mR>,<mV>,<text>
```

Differences from ASS that matter:

- Times are **three-digit milliseconds**, not ASS's centiseconds.
- A style name is **two fields joined with `_`**.
- Alpha is four separate channel fields after the four colours.
- `blur`, `angleX` and `angleY` are first-class style fields.
- `borderstyle` maps 1→0, 3→1, anything else→0.
- Only `Line=D` rows are dialogue; other types are skipped.

No real `.xss` sample survives. The only ones left are Windows installers on
the Wayback Machine under `xombie.soldats.net`, which would need extracting
without running them.

## SView — does not appear to exist

Absent from Subtitle Workshop's 67-format table, Tero Subtitler, Subtitle
Edit's 513 format classes, GNOME Subtitles, MPC-HC and TrID. The nearest
real names are SubViewer 1.0 and 2.0. Treat it as a garbled reference to
SubViewer unless a support list naming it turns up.

## Panimator — unrecoverable

The tool, its source and every sample are gone. Confirmed to have existed
(rec.arts.anime, 1992; its author was at Texas A&M) and JACOSub's `jconvert`
read it, but no grammar survives anywhere, Sconv never supported it, and no
`.pan` subtitle file exists in any archive. The only path left would be
disassembling a 1992 m68k binary.

## What was implemented, and what was not

`src/subtitld/modules/legacy.py` reads and writes **31** of these formats;
`ass.py` reads a 32nd (v4.00++). The grammars above, and the ones that came
with documentation of their own, are all implemented:

MPL2 · PJS · MPSub · VPlayer and TMPlayer · AQTitle · SubViewer 1 · Spruce ·
RealText · TurboTitle · ZeroG · ViPlay · SBT · Captions 32 · SubSonic ·
Oresme · JACOSub · Sasami2k · Xombie · MacSUB · Stream SubText player and
script · DKS · Power DivX · DVD Subtitle System · QTtext · Captionate XML ·
CMML · smilText · SSF · TeXML — plus ASS v4.00++ in `ass.py`.

**Left out on purpose:**

- **SubCreator** — no file written by it survives to check against, and its
  fraction field is one digit in Subtitle Workshop's reader and three in the
  only sample anyone quotes. A reader built on the wrong guess mistimes every
  subtitle by up to nine tenths of a second, so it waits for a real file.
- **Panimator** — the tool, its source and every sample are gone. The only
  route left is disassembling a 1992 m68k binary.
- **SView** — exists in no implementation anywhere and is almost certainly a
  garbled reference to SubViewer.

**One with no reference writer:** GPAC reads TeXML but cannot write it, and
QuickTime Pro, the only program that ever wrote it, is gone. The reader is
built from Apple's own DTD and the writer is checked by round trip alone,
which is worth knowing before trusting it with a delivery.

**A different kind of work:** Ogg Kate, Ogg Writ, OggText/Annodex, OGM text,
ASF script commands and Captionate's embedded FLV form are not sidecar files
at all — the subtitles live inside a media stream, so reading them is
demuxing rather than parsing. FFmpeg has no decoder for four of the six.

**Two names that mislead:** "SubRip 0.9" is not an early SubRip output, it is
SubViewer 1.0 under MPlayer's name for it, and MPlayer's SubRip and SubViewer
labels are transposed relative to everyone else's. "PowerDivX / DVD Subtitle
System" runs together three unrelated formats: Power DivX (`.psb`), DVD
Subtitle System (`.txt`) and DVDSubtitle (`.sub`).
